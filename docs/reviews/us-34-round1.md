# US 리뷰 — #34 Round 1

## 판정: 재작성 필요

## Critical

- [ ] **AC1 다중 API 부분 성공 시 데이터 불일치**: 개인정보 PUT 성공 후 학력 POST 실패 시 롤백/재시도 전략이 미정의. 불일치 상태로 다음 단계로 넘어갈 수 있어 구현 불가능한 AC.
- [ ] **AC3/AC5 GET→POST/PATCH 분기 중 race condition**: 동시 요청 또는 네트워크 지연으로 GET 응답 전에 중복 POST가 발생할 수 있음. "없음" 응답 계약(빈 배열 vs 404 vs null)도 미확정으로 분기 로직 테스트 불가.
- [ ] **AC3 answer 포맷 미확정**: `answer: string` 필드에 3개 문항을 어떻게 직렬화하는지(구분자, JSON 등) 미정의 → Then 절 테스트 코드 작성 불가. (플랜 자체에서 "협의 필요"로 남겨둔 상태)
- [ ] **PIPA(개인정보보호법) 별도 동의 절차 누락**: 이력서 수집(이름, 전화번호, 주소 등 민감 개인정보) 시 수집·이용 목적·보유기간을 고지하는 별도 동의 AC가 없음. 법적 필수 요건으로 구현 전 반드시 추가 필요.

## Major

- [ ] **AC2 "나중에 작성"과 protected-routing 충돌 가능성**: 온보딩 진행률 기반 라우팅이 존재할 경우 이력서를 건너뛴 사용자가 대시보드 진입 시 다시 온보딩으로 리다이렉트될 수 있음. 빈 상태 허용 여부 및 진행률 로직을 AC에 명시해야 함.
- [ ] **cover-letter/portfolio "나중에 작성" AC 누락**: AC2는 이력서에만 있고 자기소개서·포트폴리오의 건너뜀 허용 여부가 없음. 불허라면 AC3/AC5 Given에 명시 필요.
- [ ] **AC5 파일·URL 모두 없을 때 제출 가능 여부 불명확**: 포트폴리오 파일도 없고 URL도 없는 채로 "제출" 가능한지 AC에 미정의.
- [ ] **이력서 세부 항목 부분 입력 validation 기준 없음**: 학력 항목의 필수 필드(예: 학교명만 입력하고 졸업년도 미입력)에 대한 에러 케이스 AC 없음.
- [ ] **AC6 범위 불충분**: 파일 업로드 실패만 다루고 POST/PATCH 자체 실패(400, 5xx) 에러 케이스가 AC3·AC5에 없음.
- [ ] **AC8 refresh 재시도 vs 즉시 리다이렉트 미구분**: 리프레시 토큰 유효 시 갱신 후 재시도하는지, 아니면 즉시 `/login`으로 보내는지 미정의.
