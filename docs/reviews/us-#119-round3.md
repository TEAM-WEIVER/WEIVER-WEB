## 기각 / 보류

- 없음. Minor는 모두 수용했다(최종 수용 여부는 사용자가 결정).
- R2에서 기각한 "외부에서 `prevStatusRef`를 고치는 동기화 인터페이스"는 이번 M1 해결안과 다르다. 이번 안은 웹소켓 훅 **내부**의 `onConnect` 복구 순서만 바꾸고 외부 결합을 늘리지 않으므로 R2 기각 사유와 충돌하지 않는다.

## 비-LLM 오라클 정박 상태

- 코드 대조(Read)
  - `src/hooks/use-interview-websocket.ts:218-224` — `onConnect`가 `setStatus('SUBSCRIBED')` 후 재연결이면 `setStatus(prev)`를 호출한다. M1 지적과 일치.
  - `src/lib/api-client.ts:112-149` — `getCsrfToken`, `fetchReissuedAccessToken`이 `signal` 없이 `fetch`하고, `accessTokenReissuePromise`·`csrfTokenPromise`를 공유한다. M2 지적과 일치.
  - `src/store/interview-store.ts` — `AnswerAcceptedPayload`는 `interview_session_id: string`을 가진다(m4 해결안의 근거). `InterviewStatus`에 `IDLE`·`ERROR`가 있다(m2). `lastReceivedKey`는 `sessionId:sequence`이다.
- 백엔드 계약(`ANSWER_ACCEPTED.sequence` 보장, 오디오 실패 후 텍스트 답변 허용, query vs multipart)은 여전히 **미검증**이다. 확인 필요 #1·#7은 개발 착수 전 필수로 유지한다.
