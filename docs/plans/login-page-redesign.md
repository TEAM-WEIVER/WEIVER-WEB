# 개인 로그인 페이지 UI 개선 계획

작업 이슈 [#171 개인 로그인 페이지 UI 개선](https://github.com/TEAM-WEIVER/WEIVER-WEB/issues/171)

현재 `/login`은 공통 헤더 아래에서 이메일 로그인과 회원가입 진입을 제공한다. Figma의 데스크톱 시안은 연한 배경에 헤더 없이 로그인 카드를 중앙에 배치하고, 카드 안에 WEIVER 로고와 안내 문구를 표시한다. [Figma 로그인 시안](https://www.figma.com/design/usdxcZCS8IBMlBpVlDfeJ2/%EC%9C%84%EB%B2%84?node-id=2317-2842&m=dev)

## 화면 상태

| Figma 프레임 | 구현 기준                                                                                                                    |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Desktop - 17 | 입력값이 비어 있고 이메일과 비밀번호의 안내 문구가 보인다. 비밀번호는 기본적으로 가려진다.                                   |
| Desktop - 18 | 이메일과 비밀번호 입력값이 표시되고 비밀번호는 마스킹된다.                                                                   |
| Desktop - 19 | 비밀번호 보기 버튼으로 입력값을 확인할 수 있다. 시안용 스토리에서 `로그인 정보 저장`을 선택한 모습도 재현한다.               |
| Desktop - 20 | 로그인 실패 시 두 입력 필드를 오류 스타일로 표시하고 비밀번호 아래에 `이메일 또는 비밀번호가 일치하지 않습니다.`를 표시한다. |

## 구현 순서

1. `src/pages/login/page.tsx`에서 로그인 전용 중앙 카드 레이아웃을 구성한다. `public/weiver.svg`와 기존 색상·타이포그래피 토큰을 활용한다. 카드 너비는 데스크톱 시안을 기준으로 맞추고, 좁은 화면에서는 좌우 여백을 확보한다. 세로 공간이 부족하면 폼 전체를 스크롤할 수 있게 한다.
2. `LoginForm`과 `LoginFooter`에서 입력 안내 문구, `로그인` 버튼, `이메일로 회원가입` 링크를 시안에 맞춘다. 공통 `Input`, `Button`을 재사용하고 회원가입 링크는 `/signup/account-info`로 연결한다. 비밀번호 표시 토글에는 상태에 맞는 접근성 이름을 제공한다.
3. `useLoginForm`의 필수 입력 조건과 제출 중 중복 방지, 기존 인증 API와 성공 후 `/home` 이동을 재사용한다. 인증 거절은 시안 문구와 두 필드의 오류 표시로 안내하고, 네트워크·서버 장애는 일반 오류 문구로 안내한다. 오류 메시지는 보조 기술에서 인식할 수 있게 연결한다.
4. `로그인 정보 저장`, `비밀번호를 잊으셨나요?`, `카카오로 시작하기`와 `또는` 구분선은 Storybook에서 시안을 재현한다. 실제 `/login`에는 연결 가능한 기능을 노출한다. 로그인 정보 저장은 저장 대상과 정책을 확정한 뒤 구현하고, 카카오는 OAuth 연결을 확보한 뒤 노출한다. 비밀번호 찾기는 실제 재설정 라우트를 확인한 뒤 연결한다. [비밀번호 재설정 관련 이슈 #102](https://github.com/TEAM-WEIVER/WEIVER-WEB/issues/102)

## 검증 계획

- Storybook에서 빈 입력, 입력 완료, 비밀번호 표시, 로그인 실패 상태를 비교한다. 로고, 카드와 입력 간격, 오류 위치를 데스크톱 시안과 대조하고 좁은 화면에서 가로 넘침과 하단 잘림을 확인한다.
- 키보드 탭 순서, 입력 레이블, 비밀번호 표시 버튼의 접근성 이름, 오류 안내를 확인한다.
- 기존 로그인 테스트와 개인 인증 E2E의 버튼·링크 문구를 갱신한다. 로그인 성공 시 `/home` 이동, 실패 피드백, 제출 중 중복 요청 방지, 직접 접근·새로고침 및 회원가입 전환을 검증한다.
- `pnpm test src/pages/login`, `pnpm test:e2e e2e/auth/personal-auth.spec.ts`, `pnpm lint:check`, `pnpm build-storybook`을 실행한다.
