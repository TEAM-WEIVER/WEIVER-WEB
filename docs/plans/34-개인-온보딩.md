# [#34] 개인(지원자) 온보딩

## User Story

US: 신규 가입한 지원자로서, 이력서 · 자기소개서 · 포트폴리오를 순서대로 작성하고 싶다.
왜냐하면 AI 면접을 진행하기 전에 내 정보를 플랫폼에 등록해야 하기 때문이다.

---

## 전제 조건

온보딩 진입 경로는 두 가지다.

1. **신규 가입 시**: `/signup/agreements`에서 "다음" 버튼 클릭 → `POST /api/auth/applicants/signup/agreements` 호출(signupToken + 약관 동의 정보 전송) → 성공 시 응답의 `accessToken`을 클라이언트에 저장(Refresh Token은 Cookie 발급) → `/onboarding/resume`으로 자동 리다이렉트
   - PIPA 포함 모든 약관 동의는 이 시점에 서버에 저장되므로 온보딩 진입 시 별도 동의 페이지 없음
2. **재진입 시**: `/applicant/dashboard`에서 미완료 온보딩 항목(이력서·자기소개서·포트폴리오)의 작성/수정 버튼 클릭 → 해당 온보딩 단계로 직접 진입

온보딩 미완료 상태에서도 대시보드 접근은 허용한다. 대시보드는 미완료 항목에 대해 작성 유도 안내를 표시하며, 온보딩 완료 여부로 대시보드 접근을 차단하지 않는다.

## Acceptance Criteria

### AC1. 이력서 — 정상 제출

- Given: 지원자가 `/onboarding/resume` 페이지에서 필수 항목(이름, 이메일, 전화번호, 주소, 생년월일)을 모두 입력한 상태
- When: "다음" 버튼을 누른다
- Then:
  - 버튼이 즉시 disabled 처리되어 중복 제출이 방지된다
  - `PUT /api/applicants/info` (multipart/form-data)로 개인정보를 저장한다
  - 학력·자격증·수상·경력 항목이 하나라도 입력된 경우 각각 해당 엔드포인트를 호출해 전체 목록을 Snapshot 방식으로 전송한다
  - 모든 API 호출 성공 시 `/onboarding/cover-letter`로 이동한다

### AC3. 이력서 — 다중 API 부분 성공 에러 처리

- Given: 지원자가 이력서를 작성하고 "다음" 버튼을 누른 상태
- When: `PUT /api/applicants/info` 성공 후 `POST /api/applicants/education` 등 세부 항목 API 중 하나가 실패한다
- Then:
  - 토스트로 "오류가 발생했습니다. 페이지를 새로고침 후 다시 시도해주세요." 메시지가 표시된다
  - 페이지 이동은 일어나지 않는다
  - 재시도 시 전체 항목을 다시 전송한다 (성공한 항목 포함 전체 재전송)

### AC4. 이력서 — 필수 항목 미입력 유효성 검사

- Given: 지원자가 `/onboarding/resume` 페이지에서 필수 항목 일부를 입력하지 않은 상태
- When: "다음" 버튼을 누른다
- Then:
  - 비어 있는 필수 필드 각각에 인라인 에러 메시지가 표시된다 (예: "이름을 입력해주세요.")
  - API 호출 없이 폼 제출이 차단된다

### AC5. 이력서 — "나중에 작성" 건너뜀

- Given: 지원자가 `/onboarding/resume` 페이지에 진입한 상태
- When: "나중에 작성" 버튼을 누른다
- Then:
  - API 호출 없이 `/onboarding/cover-letter`로 이동한다
  - 해당 단계는 "미완료" 상태로 간주되며, 이후 대시보드(`/applicant/dashboard`)에서 이력서 작성 완료를 유도하는 안내가 표시된다

### AC6. 자기소개서 — 정상 제출

- Given: 지원자가 `/onboarding/cover-letter` 페이지에서 자기소개서(최소 1자 이상)를 작성한 상태
- When: "다음" 버튼을 누른다
- Then:
  - 버튼이 즉시 disabled 처리된다
  - 페이지 진입 시 조회한 `GET /api/applicants/document-status`의 `essayCompleted` 값으로 POST/PATCH를 결정한다
    - `essayCompleted: false` → `POST /api/essay-answers`로 `{ answer: string }` 저장
    - `essayCompleted: true` → `PATCH /api/essay-answers/{answerId}`로 `{ answer: string }` 수정 (`answerId`는 페이지 진입 시 `GET /api/essay-answers`로 미리 조회)
  - 성공 시 `/onboarding/portfolio`로 이동한다

> **answer 포맷**: 단일 `answer` 필드에 문자열로 전송. 프론트엔드에서 여러 문항을 작성하는 경우 구분자(`\n\n---\n\n`) 또는 JSON 직렬화 방식으로 병합하는 것을 백엔드와 협의 필요 (아래 "백엔드 협의 필요" 참고).

### AC7. 자기소개서 — 글자수 제한 초과

- Given: 지원자가 자기소개서 문항을 작성 중인 상태
- When: 설정된 글자수 제한을 초과한 텍스트를 입력한다
- Then:
  - 해당 필드에 인라인 에러 메시지가 표시된다
  - "다음" 버튼이 비활성화(disabled)된다

### AC8. 자기소개서 — API 실패 에러 케이스

- Given: 지원자가 자기소개서를 작성하고 "다음" 버튼을 누른 상태
- When: `POST /api/essay-answers` 또는 `PATCH /api/essay-answers/{answerId}` API가 오류를 반환한다
- Then:
  - 폼 상단 또는 토스트로 "저장 중 오류가 발생했습니다. 다시 시도해주세요." 에러 메시지가 표시된다
  - 페이지 이동은 일어나지 않는다
  - 버튼이 다시 활성화되어 재시도를 허용한다

### AC9. 자기소개서 — "나중에 작성" 건너뜀

- Given: 지원자가 `/onboarding/cover-letter` 페이지에 진입한 상태
- When: "나중에 작성" 버튼을 누른다
- Then:
  - API 호출 없이 `/onboarding/portfolio`로 이동한다
  - 해당 단계는 "미완료" 상태로 간주되며, 이후 대시보드에서 자기소개서 작성 완료를 유도하는 안내가 표시된다

### AC10. 포트폴리오 — 정상 제출

- Given: 지원자가 `/onboarding/portfolio` 페이지에서 포트폴리오 파일을 첨부하고 개인정보 이용 동의 체크박스를 체크한 상태 (URL은 선택 사항)
- When: "제출" 버튼을 누른다
- Then:
  - 버튼이 즉시 disabled 처리된다
  - 페이지 진입 시 조회한 `GET /api/applicants/document-status`의 `portfolioCompleted` 값으로 POST/PATCH를 결정한다
    - `portfolioCompleted: false` → `POST /api/portfolios` (multipart/form-data)로 저장
    - `portfolioCompleted: true` → `PATCH /api/portfolios/{portfolioId}`로 수정 (`portfolioId`는 페이지 진입 시 `GET /api/portfolios`로 미리 조회)
  - 성공 시 `/applicant/dashboard`로 이동한다

> "제출" 버튼 활성화 조건: 파일 첨부(에러 없음) + 개인정보 이용 동의 체크 두 조건이 모두 충족되어야 활성화된다.

### AC11. 포트폴리오 — 파일 용량·확장자 제한

- Given: 지원자가 포트폴리오 파일을 첨부하려는 상태
- When: 허용되지 않는 확장자 파일을 선택하거나, 허용 용량을 초과하는 파일을 선택한다
- Then:
  - 파일 선택 시 즉시 인라인 에러 메시지가 표시된다 (예: "PDF 또는 ZIP 파일만 업로드할 수 있습니다." / "파일 크기는 20MB 이하여야 합니다.")
  - 해당 파일은 첨부되지 않으며 "제출" 버튼은 비활성 상태를 유지한다
  - 에러 파일을 제거하더라도 유효한 파일이 첨부되지 않은 상태이면 "제출" 버튼은 비활성을 유지한다

### AC12. 포트폴리오 — API 실패 에러 케이스

- Given: 지원자가 포트폴리오를 작성하고 "제출" 버튼을 누른 상태
- When: `POST /api/portfolios` 또는 `PATCH /api/portfolios/{portfolioId}` API가 네트워크 오류 또는 서버 오류(5xx)를 반환한다
- Then:
  - 폼 내부 또는 토스트로 "업로드 중 오류가 발생했습니다. 다시 시도해주세요." 에러 메시지가 표시된다
  - 페이지 이동은 일어나지 않는다
  - 버튼이 다시 활성화되어 재시도를 허용한다

### AC13. 포트폴리오 — "나중에 작성" 건너뜀

- Given: 지원자가 `/onboarding/portfolio` 페이지에 진입한 상태
- When: "나중에 작성" 버튼을 누른다
- Then:
  - API 호출 없이 `/applicant/dashboard`로 이동한다
  - 해당 단계는 "미완료" 상태로 간주되며, 이후 대시보드에서 포트폴리오 작성 완료를 유도하는 안내가 표시된다

### AC14. 공통 — API 호출 중 로딩 처리

- Given: 지원자가 각 단계에서 "다음" 또는 "제출" 버튼을 누른 상태
- When: API 요청이 진행 중이다
- Then:
  - 버튼이 비활성화되어 중복 제출이 방지된다
  - 로딩 인디케이터(스피너 또는 버튼 내 로딩 상태)가 표시된다

### AC15. 공통 — 인증 만료 또는 미인증 접근

- Given: 액세스 토큰이 만료되었거나 없는 상태
- When: 온보딩 페이지에 접근하거나 API를 호출한다
- Then:
  - api-client 레이어에서 refresh 토큰으로 재발급을 시도한다
  - refresh도 실패하면(401) `/login`으로 리다이렉트된다

### POST/PATCH 분기 기준

- `GET /api/applicants/document-status`를 페이지 진입 시 호출해 `essayCompleted` / `portfolioCompleted` 값으로 분기를 결정한다
- 신규 가입 직후에는 모두 `false`이므로 항상 POST 경로를 탄다
- 재진입 시(`true`) `GET /api/essay-answers` 또는 `GET /api/portfolios`를 추가 호출해 기존 데이터로 폼을 pre-fill하고 `answerId` / `portfolioId`를 확보한다

### 백엔드 협의 필요 항목

1. **자기소개서 answer 포맷**: 프론트엔드에서 여러 문항을 작성하는 경우 단일 `answer` 필드에 병합 방식(구분자, JSON 직렬화 등) 확인 필요.
2. **포트폴리오 urlTech 필드 매핑**: 클라이언트 스키마에서 `notionUrl`로 명명되어 있고 API 스펙에서는 `urlTech`로 명명되어 있어 매핑 기준 확인 필요.
3. ~~**포트폴리오 파일·URL 모두 없을 때 제출 가능 여부**~~ → AC10에서 파일 첨부 필수로 결정. 협의 불필요.
4. **이력서 재방문 수정 시나리오**: 온보딩 최초 저장은 POST, 이후 수정은 별도 엔드포인트(PUT/PATCH) 필요 여부 확인.
5. ~~**GET /api/essay-answers "없음" 응답 계약**~~ → `GET /api/applicants/document-status`로 분기 결정 방식으로 변경. 협의 불필요.
6. ~~**GET /api/portfolios "없음" 응답 계약**~~ → 동일 이유로 협의 불필요.

## 컴포넌트 스펙

- 사용할 shadcn/ui 컴포넌트: `Button`, `Input`, `Textarea`, `Checkbox`, `Form` (이미 구현 완료)
- 상태 관리 필요 여부: API 로딩·에러 상태는 각 페이지 로컬 상태(`useState`) 또는 React Query 사용. 온보딩 진행 상태(`OnboardingProgress`, 각 단계 완료/미완료 여부)는 Zustand 스토어에서 관리.
- 접근성 주의사항:
  - 버튼 로딩 중 `aria-busy="true"` 및 `aria-disabled="true"` 처리
  - 에러 메시지는 `role="alert"` 또는 `aria-describedby`로 필드와 연결
  - 파일 드롭존에 `role="region"`, `aria-label` 지정
  - PIPA 동의 체크박스는 `aria-required="true"` 처리
