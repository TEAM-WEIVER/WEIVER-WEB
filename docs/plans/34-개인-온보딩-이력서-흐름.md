# [#34] 개인 온보딩 이력서 구현 흐름

## 목적

`/onboarding/resume`은 지원자의 기존 이력서 데이터를 한 번 조회한 뒤, 조회된 값을 각 입력 필드에 채워 넣고, 사용자가 수정한 최종 상태를 다음 버튼에서 저장한다.

핵심 원칙은 다음과 같다.

- 페이지 진입 시 `GET /api/applicants` 한 번으로 개인정보, 학력, 수상, 자격증, 경력을 모두 가져온다.
- 조회된 값은 폼 필드에 그대로 채운다.
- 사용자가 수정한 최종 폼 상태를 저장한다.
- 학력, 수상, 자격증, 경력은 기존 데이터 존재 여부에 따라 `POST`와 `PUT`을 분기한다.

## 조회 흐름

페이지 진입 시 `GET /api/applicants`를 호출한다.

응답 예시는 다음 형태다.

```json
{
  "status": "success",
  "code": 200,
  "data": {
    "ApplicantDTO": {
      "photoUrl": null,
      "name": "김민채",
      "birthday": "2001-07-30",
      "phoneNumber": "010-8975-1978",
      "email": "rlawlsdl0730@gmail.com",
      "address": "경기도 안산시 상록구 한양대학로 55"
    },
    "EducationDTO": [],
    "AwardDTO": [],
    "WorkExperienceDTO": [],
    "CertificateDTO": []
  },
  "message": null
}
```

응답 데이터는 `mapApplicantsToResumeForm()`에서 React Hook Form 형태로 변환한 뒤 `reset(resumeForm)`으로 주입한다.

개인정보 입력 필드는 `Controller`로 연결한다. 초기 조회값이 들어온 뒤에도 화면에 안정적으로 표시되어야 하므로 `value={field.value ?? ''}` 형태의 controlled input을 유지한다.

학력, 수상, 자격증, 경력처럼 배열로 관리되는 영역은 `useFieldArray`를 사용한다. `reset()` 이후 각 배열 값이 필드 배열에도 반영되어야 한다.

## 개인정보 저장

다음 버튼을 누르면 개인정보는 `PUT /api/applicants/info`로 저장한다.

요청은 `multipart/form-data`이며, `requestDTO` Blob에 다음 값을 담는다.

```json
{
  "name": "김민채",
  "email": "rlawlsdl0730@gmail.com",
  "phoneNumber": "010-8975-1978",
  "address": "경기도 안산시 상록구 한양대학로 55",
  "birthday": "2001-07-30"
}
```

프로필 이미지는 선택값이다. 이미지가 없는 경우 `requestDTO`만 전송한다.

## 경력 조회 매핑

`GET /api/applicants`의 `WorkExperienceDTO`는 폼의 경력 필드로 변환한다.

백엔드 응답의 `experienceId`는 프론트 폼에서는 `workExperienceId`로 보관한다. 이후 수정 저장 시 기존 항목임을 백엔드가 알 수 있도록 이 값을 다시 전송한다.

```ts
{
  workExperienceId: experience.experienceId,
  companyName: experience.companyName,
  startDate: experience.startDate,
  endDate: experience.endDate,
  employmentType: enumToLabel(experience.employmentType),
  position: experience.position,
  duties: experience.duties,
  isRecognized: experience.isRecognized ?? undefined,
}
```

## 경력 저장 분기

페이지 진입 시 조회한 `WorkExperienceDTO`가 빈 배열인지 여부를 저장해 둔다. 이 값은 다음 버튼에서 `POST`와 `PUT`을 결정하는 기준이다.

- 최초 저장: 조회 당시 `WorkExperienceDTO`가 빈 배열이면 `POST /api/applicants/experience`
- 수정 저장: 조회 당시 `WorkExperienceDTO`가 하나라도 있으면 `PUT /api/applicants/experience`

`POST` 요청은 새 항목만 저장하는 초기 등록 요청이므로 id를 보내지 않는다.

```json
{
  "WorkExperienceDTO": [
    {
      "companyName": "쿠팡플레이",
      "startDate": "2019-03-01",
      "endDate": "2024-08-01",
      "employmentType": "FULL_TIME",
      "position": "대리",
      "duties": "백엔드 개발",
      "isRecognized": true
    }
  ]
}
```

`PUT` 요청은 화면에 남아 있는 최종 경력 리스트 전체를 덮어쓴다. 기존 항목은 `workExperienceId`를 포함하고, 새로 추가한 항목은 id 없이 보낸다.

```json
{
  "WorkExperienceUpdateDTO": [
    {
      "workExperienceId": 1,
      "companyName": "쿠팡플레이",
      "startDate": "2019-03-01",
      "endDate": "2024-08-01",
      "employmentType": "FULL_TIME",
      "position": "대리",
      "duties": "백엔드 개발",
      "isRecognized": true
    },
    {
      "companyName": "새 회사",
      "startDate": "2025-01-01",
      "endDate": "2025-06-01",
      "employmentType": "INTERN",
      "position": "인턴",
      "duties": "서비스 개발",
      "isRecognized": false
    }
  ]
}
```

기존 경력이 있었는데 사용자가 모든 경력을 삭제한 경우에도 `PUT`을 호출하고 빈 배열을 보낸다. 삭제도 최종 리스트 덮어쓰기의 일부로 처리한다.

## 자격증 조회 매핑

`GET /api/applicants`의 `CertificateDTO`는 폼의 자격증 필드로 변환한다.

백엔드 응답의 `certificateId`는 프론트 폼에서도 `certificateId`로 보관한다. 이후 수정 저장 시 기존 항목임을 백엔드가 알 수 있도록 이 값을 다시 전송한다.

```ts
{
  certificateId: certificate.certificateId,
  acquisitionDate: certificate.acquisitionDate,
  certificateName: certificate.certificateName,
  issuer: certificate.issuer,
}
```

## 자격증 저장 분기

페이지 진입 시 조회한 `CertificateDTO`가 빈 배열인지 여부를 저장해 둔다. 이 값은 다음 버튼에서 `POST`와 `PUT`을 결정하는 기준이다.

- 최초 저장: 조회 당시 `CertificateDTO`가 빈 배열이면 `POST /api/applicants/certificate`
- 수정 저장: 조회 당시 `CertificateDTO`가 하나라도 있으면 `PUT /api/applicants/certificate`

`POST` 요청은 새 항목만 저장하는 초기 등록 요청이므로 id를 보내지 않는다.


```json

    {
```

기존 자격증이 있었는데 사용자가 모든 자격증을 삭제한 경우에도 `PUT`을 호출하고 빈 배열을 보낸다. 삭제도 최종 리스트 덮어쓰기의 일부로 처리한다.

## 학력 저장 분기

페이지 진입 시 조회한 `EducationDTO`가 빈 배열인지 여부를 저장해 둔다.

- 최초 저장: 조회 당시 `EducationDTO`가 빈 배열이면 `POST /api/applicants/education`
- 수정 저장: 조회 당시 `EducationDTO`가 하나라도 있으면 `PUT /api/applicants/education`

`POST` 요청은 `EducationDTO` 배열로 보낸다.

```json
{
  "EducationDTO": [
    {
      "degreeType": "ASSOCIATE",
      "schoolName": "한양대학교",
      "major": "컴퓨터학부",
      "gpa": 4.1,
      "startDate": "2021-03",
      "endDate": "2027-03",
      "status": "ACTIVE"
    }
  ]
}
```

`PUT` 요청은 `EducationUpdateDTO` 배열로 보낸다. 기존 항목은 `educationId`를 포함하고, 새로 추가한 항목은 id 없이 보낸다.

```json
{
  "EducationUpdateDTO": [
    {
      "educationId": 1,
      "degreeType": "ASSOCIATE",
      "schoolName": "한양대학교",
      "major": "컴퓨터학부",
      "gpa": 4.1,
      "startDate": "2021-03",
      "endDate": "2027-03",
      "status": "ACTIVE"
    }
  ]
}
```

기존 학력이 있었는데 사용자가 모든 학력을 삭제한 경우에도 `PUT`을 호출하고 빈 배열을 보낸다.

## 학력 enum 매핑

학력구분과 졸업상태는 UI에는 한글 라벨을 표시하고, API에는 enum 값을 보낸다.

| degreeType API enum | UI label      |
| ------------------- | ------------- |
| `HIGH_SCHOOL`       | 고등학교      |
| `ASSOCIATE`         | 대학교(2,3년) |
| `BACHELOR`          | 대학교(4년)   |
| `MASTER`            | 대학원(석사)  |
| `DOCTOR`            | 대학원(박사)  |

| status API enum        | UI label |
| ---------------------- | -------- |
| `GRADUATED`            | 졸업     |
| `LEAVE_OF_ABSENCE`     | 휴학중   |
| `GRADUATION_POSTPONED` | 졸업예정 |
| `ACTIVE`               | 재학중   |

## 고용 형태 매핑

UI에는 한글 라벨을 표시하고, API에는 enum 값을 보낸다.

| API enum                     | UI label   |
| ---------------------------- | ---------- |
| `FULL_TIME`                  | 정규직     |
| `INTERN`                     | 인턴       |
| `CONTRACT`                   | 계약직     |
| `FREELANCER`                 | 프리랜서   |
| `MILITARY_SERVICE_EXEMPTION` | 병역특례   |
| `PART_TIME`                  | 아르바이트 |

조회 시에는 enum을 한글 라벨로 변환하고, 저장 시에는 한글 라벨을 enum으로 다시 변환한다.

## 현재 적용 범위

현재 확정된 핵심 흐름은 개인정보 pre-fill과 학력, 수상, 자격증, 경력 저장 분기다.

배열형 도메인은 모두 같은 원칙을 따른다. 조회 당시 기존 데이터가 없으면 `POST`, 기존 데이터가 있으면 화면의 최종 리스트 전체를 `PUT`으로 보낸다.

## 검증 기준

최소 검증 케이스는 다음과 같다.

- `GET /api/applicants` 응답의 개인정보가 이름, 생년월일, 이메일, 전화번호, 주소 입력 필드에 표시된다.
- 기존 경력이 없으면 다음 버튼에서 `POST /api/applicants/experience`가 호출된다.
- 기존 경력이 있으면 다음 버튼에서 `PUT /api/applicants/experience`가 호출되고 기존 항목의 `workExperienceId`가 포함된다.
- 기존 경력이 있던 상태에서 모두 삭제하면 `PUT /api/applicants/experience`에 빈 배열을 보낸다.
- 기존 자격증이 없으면 다음 버튼에서 `POST /api/applicants/certificate`가 호출된다.
- 기존 자격증이 있으면 다음 버튼에서 `PUT /api/applicants/certificate`가 호출되고 기존 항목의 `certificateId`가 포함된다.
- 기존 자격증이 있던 상태에서 모두 삭제하면 `PUT /api/applicants/certificate`에 빈 배열을 보낸다.
- 기존 학력이 없으면 다음 버튼에서 `POST /api/applicants/education`이 호출된다.
- 기존 학력이 있으면 다음 버튼에서 `PUT /api/applicants/education`이 호출되고 기존 항목의 `educationId`가 포함된다.
- 기존 학력이 있던 상태에서 모두 삭제하면 `PUT /api/applicants/education`에 빈 배열을 보낸다.
- 기존 수상이력이 없으면 다음 버튼에서 `POST /api/applicants/award`가 호출된다.
- 기존 수상이력이 있으면 다음 버튼에서 `PUT /api/applicants/award`가 호출되고 기존 항목의 `awardId`가 포함된다.
- 기존 수상이력이 있던 상태에서 모두 삭제하면 `PUT /api/applicants/award`에 빈 배열을 보낸다.
