## 자동 검증 불가 이유

실제 이메일 인증번호를 수신해야 `signupToken`이 발급되고, 해당 토큰 없이는 `/signup/agreements` 페이지에 진입 불가(AC11 리다이렉트). Playwright mock으로 우회 시 실제 API 연동 검증이 누락되므로 수동 테스트로 대체.

---

## 회원가입 완료 이후 온보딩 E2E 테스트 한계

### 현재 구조
```
브라우저 → Next.js Route Handler(/api/auth/signup/complete) → httpOnly cookie 세팅 → /onboarding/resume
```

### 문제
- `page.route()`로 agreements API를 mock해도 Route Handler가 실행되지 않아 httpOnly cookie가 세팅되지 않음
- cookie 없이 `/onboarding/resume` 접근 시 middleware가 로그인으로 리다이렉트

### 가능한 우회 방법 (백엔드 협의 필요)

권장안은 E2E/test 환경에서만 테스트 전용 이메일에 대해 CI secret 또는 환경변수로 주입된 인증번호를 허용하는 방식이다.

자세한 정책은 [이메일 인증 E2E 테스트 정책](../testing/email-verification-e2e.md)을 따른다.

### 현재 결론

백엔드에서 E2E 전용 secret 기반 인증번호 정책을 지원하기 전까지 회원가입 완료 이후 플로우(온보딩, 보호 라우트)는 수동 테스트로 대체.
